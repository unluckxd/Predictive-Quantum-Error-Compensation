# PQEC Architecture

## Scope

PQEC is a simulation prototype for estimating coherent single-qubit pulse-angle drift from an auxiliary probe qubit, then adjusting the next target operation. The controller receives probe readout history only. It never receives the target qubit's state or the simulator's hidden error values.

The nominal shared-drift case assumes that the probe and target qubit experience the same pulse-angle error trajectory. The independent-noise and probe-mismatch cases deliberately test that assumption.

## Data path

```mermaid
flowchart LR
    H[Prior probe readouts] --> E[Readout correction and angle estimate]
    E --> W[Rolling history: up to 16 checkpoints]
    W --> F[Guarded linear forecast for next cycle]
    F --> C[Command Rx: 90 degrees minus forecast]
    C --> L[Target qubit]
    D[Control error trajectory] --> L
    D --> P[Separate auxiliary probe sequence]
    P --> R[Y-basis measurement]
    R --> E
    L -. simulator-only scoring .-> S[Offline metric calculation]
```

The dashed path is used only to calculate simulation metrics after the run. It is not available to the controller. The diagram represents the modeled common-drift path; the independent and mismatch conditions replace that shared relationship with separate error trajectories.

## Probe and estimator

At each checkpoint, the simulator prepares the auxiliary probe in $|+y\rangle$, applies $m=13$ rotations $R_x(90^\circ+\delta_p)$, then measures along Y by applying $S^\dagger$, H, and computational-basis readout. Each checkpoint uses the configured number of shots. A startup checkpoint is taken before the target sequence; later checkpoints follow the configured interval.

The readout counts are corrected using the configured symmetric readout-error estimate. The signed angle estimate is recovered from the Y-basis probability. Details and equations are in [the mathematical model](mathematical_model.md).

## Controllers

- **Reactive last probe:** for a target operation, subtract the newest probe estimate whose checkpoint precedes that operation.
- **Predictive linear:** fit a line to up to the latest 16 probe estimates and extrapolate it to the next pulse.
- **Guarded PQEC:** fit the same rolling line, but suppress weak trends and shrink stronger slopes. The forecast is anchored to the latest measurement. When the trend is not supported, it falls back to the latest reading.
- **Robustness baselines:** a 16-reading moving average, per-cycle exponential moving average, two-point linear extrapolator, and constant-velocity Kalman filter. Their settings are fixed in `configs/robustness_v03.json` and are not retuned for each condition.

The guarded defaults are a trend threshold of 2, at least 4 readings before a trend is used, and a 16-checkpoint history. The threshold is a heuristic in this prototype; it is not a hardware-calibrated confidence test.

## Comparison methods

The simulator also reports an ideal reference, an oracle upper bound that knows the true upcoming error, no compensation, one-time static calibration, and a simplified randomized-compiling baseline. The oracle is not implementable from probe history. The randomized-compiling baseline randomizes the sign of an X-axis coherent error in the model; it does not implement circuit-level Pauli twirling, correction compilation, or Pauli-frame tracking.

Reactive and predictive methods use the same probe record within each paired run. This holds measurement noise and the modeled trajectory fixed while comparing controller rules. The expanded conditions and their failure cases are described in [the robustness report](robustness_v03.md).

## Aer noise-model path

The Aer v0.1/v0.2 path uses a five-pulse Y-basis probe and a noisy response lookup table generated by Aer with the configured probe T1/T2, depolarizing channels, and asymmetric readout matrix. The controller receives only finite-shot probe counts and converts them to a probe-angle estimate through this fixed lookup table. That assumes the probe-noise and readout calibration parameters are already known exactly.

The target path applies its own T1/T2 and depolarizing channels after each Rx gate. At each non-final probe checkpoint, an explicit idle channel is applied to the target for the modeled serial acquisition duration plus classical controller latency. Controllers in a paired run share the same target trajectory, probe record, and wait schedule. The no-compensation control does not acquire a probe and therefore has no modeled probe wait.

Aer's final target density matrix is used only for offline scoring against the ideal 61-pulse output. It is not exposed to the control logic. Full channel values, timing assumptions, limitations, and the expanded mismatch results are in [the Aer v0.2 report](aer_noise_v02.md); the initial four-condition pilot is preserved in [the Aer v0.1 report](aer_noise_v01.md).
