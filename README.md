# Predictive Quantum Error Compensation

## Выбор для первой версии

Первая версия проверяет **А: прогноз систематического когерентного дрейфа до следующего импульса**. Измерения вспомогательного пробника дают историю наблюдений; критерий метода — улучшает ли прогноз точность следующего импульса по сравнению с калибровкой и использованием последнего наблюдения.

Ожидаемый результат ограничен: прогноз должен помогать при медленно меняющемся смещении угла. Независимую случайную составляющую он предсказать не должен.

## Однокубитный эксперимент

Скрипт pqec_single_qubit.py применяет к логическому кубиту последовательность целевых поворотов Rx(90°). Скрытая ошибка каждого импульса δₖ добавляется к заданному углу. Контроллер получает данные только от отдельного калибровочного кубита и выбирает поправку до следующего логического импульса.

Для калибровки отдельный кубит готовится в состоянии |+y⟩ и получает те же целевые импульсы Rx(90° + δ), что и логический кубит. Измерение по Y реализовано поворотами S† и H, после которых состояние измеряется в вычислительном базисе Z. При m = 4k + 1 импульсах вероятность нулевого исхода равна P(0) = (1 - sin(mδ)) / 2, поэтому знак угловой ошибки оценивается как δ̂ = -arcsin(2n₀/shots - 1)/m. При запуске скрипт сравнивает эту вероятность с прямым ожиданием оператора Паули Y и формулой; максимальная разность печатается.

В расчёте есть три условия:

- slow_drift: начальное смещение 2°, линейный дрейф логического кубита и пробника 0,01° за цикл, небольшой общий остаток;
- white_noise: логический кубит и пробник получают независимый белый шум σ = 0,20° при общем среднем смещении;
- probe_mismatch: логический кубит дрейфует на 0,01° за цикл, пробник — на 0,03°, с отдельным смещением 0,20° и локальным шумом σ = 0,05°.

Для каждого прогона сравниваются отсутствие компенсации, разовая калибровка, поправка по последнему пробнику, линейный прогноз PQEC и randomized compiling. Oracle использует скрытую истинную ошибку и служит только недостижимой верхней границей; идеальный ряд служит эталоном. RC обозначен как **упрощённый sign-flip baseline**: случайный знак когерентной ошибки моделирует эффект Pauli twirling для этих повторяющихся Clifford-поворотов. Это не полноценная реализация randomized compiling с компиляцией Паули и отслеживанием Pauli frame. На один прогон используется одна случайная компиляция.

В probe_mismatch пробник имеет 2% симметричной ошибки считывания, а поправка использует оценку калибровки 1%. В остальных условиях оба значения равны 1%. Измерения считывания моделируются как битовые перевороты; стоимость калибровки считывания не включена.

Все практические контроллеры получают один и тот же набор вспомогательных измерений на каждом парном прогоне. Бюджет на прогон равен (число циклов + 1) × shots измерений и на m пробных поворотов в каждом измерении. Поправка PQEC встраивается в угол импульса и не добавляет отдельный логический вентиль. В итоговом CSV выводится время классического расчёта на одну последовательность. Оно измеряется на текущем компьютере; жёсткий срок выполнения контроллера и задержка реального процессора этим симулятором не моделируются.

Fidelity состояний считается точно по Statevector, без конечного числа измерений выходного логического состояния. Конечный бюджет shots применяется к вспомогательному пробнику. Поэтому результаты проверяют математическую состоятельность оценивания и управления, но не включают затраты на томографию или считывание итогового состояния на устройстве.

## Метрики

- средняя fidelity состояния по всем префиксам схемы и fidelity после последнего импульса;
- средняя однокубитная average gate fidelity;
- RMS остаточной ошибки угла после компенсации;
- RMS накопленного углового отклонения;
- MAE прогноза следующего угла для PQEC;
- число вспомогательных измерений и пробных поворотов.

## Статистический план

По умолчанию выполняются 100 прогонов на каждом из двух независимых seed-блоков: всего 200 парных прогонов на условие. Внутри пары все методы получают одну и ту же траекторию и историю измерений пробника. CSV с результатами хранит отдельную строку для каждого метода, прогона, seed-блока и начального seed.

Основное сравнение — прогноз PQEC минус реакция на последнее измерение. Для конечной state fidelity и двух RMS-метрик считаются парный percentile-bootstrap 95% CI и двусторонний sign-flip permutation test; тест предполагает обменяемость знаков парных разниц при нулевой гипотезе. Значения p корректируются методом Холма по девяти сравнениям, доверительные интервалы остаются нескорректированными 95% интервалами. В таблице статистики также сохраняются средние эффекты по каждому seed-блоку, чтобы видеть зависимость вывода от случайной последовательности.

## Результаты Qiskit-прогона

Запуск выполнен через Qiskit Statevector 2.6.1: 200 парных прогонов на условие, 64 логических импульса, 4096 shots на измерение пробника и 13 импульсов пробника. В таблице указана разница «PQEC − последнее измерение». Для fidelity положительное значение лучше; для RMS-ошибок отрицательное значение лучше.

| Независимый белый шум | RMS ошибки на импульс | −0,04561° | [−0,04908°; −0,04233°] | <0,001 |
| Независимый белый шум | RMS накопленного угла | +0,20512° | [+0,12259°; +0,28841°] | <0,001 |

При общем медленном дрейфе выигрыш в конечной fidelity мал, но статистически различим после поправки Холма; RMS ошибки отдельного импульса также снижается. Для RMS накопленного угла CI включает ноль. В обоих независимых seed-блоках знак разницы конечной fidelity и RMS ошибки импульса совпал.

Для белого шума CI разницы конечной fidelity включает ноль. Сглаживание уменьшило RMS ошибки одного импульса, однако увеличило RMS накопленного угла; MAE прогноза 0,1933° близка к заданному шуму σ = 0,20°. Это не свидетельствует о прогнозировании независимой случайной составляющей.

При рассогласовании пробника прогноз существенно ухудшился: этот сценарий показывает, что компенсация зависит от того, насколько точно дрейф пробника представляет дрейф логического кубита.

На один прогон из 64 логических импульсов расходуется 266 240 вспомогательных shots и 3 461 120 пробных поворотов. Fidelity логического состояния вычисляется точно через Statevector; конечное число shots применяется только к пробнику. Накладные расходы на томографию результата и на калибровку считывания не включены.

## Запуск

Нужен Python 3.10 или новее. Для использования симулятора Qiskit установите зависимость:

~~~powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python pqec_single_qubit.py
~~~

С установленным Qiskit состояния вычисляются через qiskit.quantum_info.Statevector.from_instruction ([официальный API](https://docs.quantum.ibm.com/api/qiskit/2.0/qiskit.quantum_info.Statevector)); без Qiskit скрипт использует точную аналитическую модель одного кубита, чтобы расчёт оставался воспроизводимым в минимальном окружении.

Сводка, результаты каждого парного прогона и статистический анализ сохраняются соответственно в results/pqec_single_qubit_summary.csv, results/pqec_single_qubit_runs.csv и results/pqec_single_qubit_paired_stats.csv. Чтобы проверить новые случайные последовательности, задайте другой seed и отдельные пути, например --seed 731003 --output results/seed_731003_summary.csv --runs-output results/seed_731003_runs.csv --paired-output results/seed_731003_stats.csv. Параметры дрейфа и число прогонов можно менять аргументами командной строки. Пакет Qiskit устанавливается по [официальной инструкции](https://docs.quantum.ibm.com/guides/install-qiskit).

## Границы прототипа

Это проверка модели управления, а не эксперимент на реальном устройстве. Пробник не проверяет коррекцию произвольных ошибок на неизвестном логическом состоянии. Модель не включает декогеренцию, утечку, кросс-ток, неодинаковую динамику всех физических кубитов и стоимость томографии. Условия общего дрейфа и рассогласования пробника делают предположение о переносимости его оценки явным. Полноценный circuit-level randomized compiling и проверка запутанной пары остаются следующими отдельными этапами.
